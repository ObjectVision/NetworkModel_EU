# Issue #48 — frontier projection data

Data behind deck pages **62/63** ("Baselines and their frontier projections") plus the
full per-λ sweep results, per area and for the aggregate.

Generated by `doc/export_issue48.py` from `doc/deck_data.json` — **no new solves**; it
reuses the exact functions that produced the deck charts (`frontier_metrics.metrics_for`,
`build_charts._interp_at`).

## Files

| File | Rows | Contents |
|---|---|---|
| `issue48_crossings.csv` | 86 | Per area × cost function (+ `AGGREGATE`): the S1/B/S2 rectangle, its diagonal crossing with the Pareto frontier, and λ at that crossing |
| `issue48_sweep_results.csv` | 1626 | Per area × cost function × λ: found travel cost and facility cost at every swept λ |

`region = AGGREGATE` is the sum over the **41 disjoint areas** (Poland-country excluded
because its 7 NUTS-1 areas are present). Because the objective separates by area, summing
the regional optima at a **common λ** is exact for the combined problem.

## `issue48_crossings.csv`

| Column | Meaning |
|---|---|
| `region`, `func` | area; `LINEAR` or `LOGISTIC` travel-cost function |
| `B_facilities`, `B_travelcost` | baseline point **B** = current network (count, travel cost) |
| `S1_travelcost` | travel cost at the baseline facility **count** (vertical drop from B) |
| `S2_facilities` | facility count at the baseline **travel cost** (horizontal drop from B) |
| `corner_facilities`, `corner_travelcost` | corner **C** = (S2_facilities, S1_travelcost) — the opposite rectangle corner |
| `rect_area_raw` | (B_x − S2_x) × (B_y − S1_y), raw units (facilities × travel cost) |
| `rect_rel` | size-independent: (fractional facility saving) × (fractional travel saving), in [0,1] |
| `cross_facilities`, `cross_travelcost` | **the requested point**: where the frontier crosses the B→C diagonal (balanced improvement) |
| `lambda_cross_eur`, `w_cross` | λ at the crossing, in EUR (λ = w × 100 000) |
| `cross_facilitycost_eur` | λ_cross × cross_facilities |
| `cross_totalcost_eur` | cross_facilitycost + cross_travelcost |
| `s1_bracketed`, `s2_bracketed` | whether the swept λ-range actually spans that target (`False` ⇒ clamped, treat as a bound) |
| `n_frontier_pts` | number of points on the Pareto envelope |

## Method notes / caveats

- **Interpolation.** S1/S2 and the crossing are linearly interpolated (chord) between the
  two bracketing frontier points. The frontier is convex, so chords slightly
  **over-estimate** it — `S1_travelcost`, `rect_area_raw` and the crossing are mild upper
  bounds. The exact soft-coverage p-median MIP (todo #5) would pin them exactly.
- **Soft coverage.** Clients may be left unserved at a fixed penalty (BIG = c(120 min) for
  LINEAR, saturation 1 for LOGISTIC); the baseline is priced the same way, so B and the
  frontier are comparable.
- **Currency.** λ is expressed against the placeholder facility fixed cost of
  €100 000 (`FACILITY_MIN_COSTS`); real pharmacy `a,b` are not yet calibrated (todo D15),
  so treat EUR amounts as **relative**, not absolute.
- **Large regions.** FRI and PL8 were solved on a subsampled candidate set that retains
  every baseline location, so their frontier still dominates their baseline.

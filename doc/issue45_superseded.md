## Superseded — the S1/S2 open-location tables have been regenerated

The three batches posted in this issue were computed on road networks that pruned island
subnetworks. That has been fixed (#49, #50), so **every file delivered here is stale** and
should be replaced by the attached `s1s2_open_locations_postfix.zip` (168 files, 0.5 MB).

### What changed

1. **Landbody-complete networks.** The largest strongly-connected road network is now kept
   for *every* separate landbody, not just the single largest one in the study area. Island
   networks and their ferry links were being discarded. ITG is the extreme case: its
   baseline mean travel time fell from **22.3 to 4.9 min** and its unreachable residents
   from **983,169 to 591**, because Sardinia had no network at all before.
2. **Region exclusion.** A NUTS region where more than 50 % of inhabitant locations cannot
   reach any pharmacy is now dropped entirely — population *and* candidate locations. This
   removes the **Azores (PT200)** and **Madeira (PT300)**, which hold population but no
   pharmacy anywhere in the source data. Portugal's baseline travel cost falls **−62 %**.
   Its figures now cover the **mainland only**.

Five areas moved: ITG, PL8, Portugal, SE2, SE3. The other 37 are unchanged, so their files
are byte-identical to the previous delivery — but the zip contains all 42 for consistency.

### ⚠ The file naming changed

| | |
|---|---|
| batches 1–3 | `<region>_<S1\|S2>_<LINEAR\|LOGISTIC>_open.arrow` |
| **now** | `<region>_<s1\|s2>_<linear\|logistic>_open.arrow` |

Lower case, because that is what `cfg/main/SourceData/Locations.dms` `services_allocated`
reads literally. On Windows the two forms are the same file, so this only matters once the
files are unzipped somewhere case-sensitive — but a zip stores one name, so the form the
config asks for is the safe one to ship.

Format is otherwise unchanged: two columns `x, y` in **EPSG:3035 / LambertEA**, one row per
open facility.

### Coverage

All **42 swept study areas** × {S1, S2} × {LINEAR, LOGISTIC} = 168 files, 169,579 open
locations. (`services_allocated` currently lists 21 areas; the other 21 are available in
the same zip and the same naming if you want to widen it.)

Generated by `export_s1s2_locations.jl`, which replaces the three ad-hoc scratch exporters
used for the original batches.
